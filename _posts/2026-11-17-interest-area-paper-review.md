### 논문: Prompt Injection Attack to Tool Selection in LLM Agents

저자: Jiawen Shi 외 5명

링크: [https://doi.org/10.14722/ndss.2026.230675](https://doi.org/10.14722/ndss.2026.230675)

이 논문이 다루는 문제는 무엇인가? 

- LLM 에이전트가 외부 도구를 선택할 때, 악성 도구 문서로 인해 공격자가 원하는 도구를 선택하게 되는 문제이다.

왜 이 문제가 중요한가?

- 도구 선택은 LLM 에이전트의 핵심 과정이며, 이 과정이 조작되면 에이전트가 정상 도구 대신 공격자의 악성 도구를 선택할 수 있기 때문이다.

기존 방식들은 무엇이 부족했는가?

- 기존 프롬프트 인젝션 공격은 도구 선택 문제에 적용했을 때 효과가 충분하지 않았다. 이에 저자들은 악성 도구가 검색되고 최종 선택되도록 두 단계로 최적화하는 ToolHijacker를 제안했다.

### 기승전결 리뷰:

기

LLM 에이전트는 사용자의 요청을 처리하기 위해 검색, 계산, API 등의 외부 도구를 선택한다. 도구가 많을 때는 먼저 관련 도구를 검색한 뒤, LLM이 검색된 후보 중 하나를 최종 선택한다. 그러나 공격자가 악의적인 설명이 포함된 도구를 등록하면 에이전트가 정상 도구 대신 공격자의 도구를 선택할 수 있다. 기존 공격은 주로 최종 선택 단계만 조작했기 때문에, 악성 도구가 검색되지 않으면 공격이 성공하기 어려웠다. 이 논문은 공격자가 실제 사용자 질문이나 표적 모델의 내부 정보를 모르는 상황에서도 검색과 선택을 모두 조작할 수 있는지를 핵심 문제로 다룬다.

승

논문은 악성 도구 설명을 자동으로 만드는 **ToolHijacker**를 제안한다. 악성 설명은 크게 R과 S 두 부분으로 구성된다. R은 악성 도구가 사용자 요청과 관련된 것처럼 보여 검색 후보에 포함되도록 하고, S는 검색된 후보 중 LLM이 악성 도구를 최종 선택하도록 유도한다.

공격자는 실제 시스템에 직접 접근하는 대신, 대리 LLM·대리 검색기·대리 질문·대리 도구 목록으로 구성된 환경에서 악성 문서를 제작한다. 제작 방법은 LLM을 이용해 자연스러운 설명을 반복적으로 개선하는 기울기 비사용 방식과, 모델의 기울기를 이용해 공격에 유리한 토큰을 찾는 기울기 기반 방식으로 나뉜다. 완성된 악성 문서를 실제 도구 플랫폼에 등록하여 다른 모델과 검색기에서도 공격이 전이되는지를 확인한다.

전

연구진은 MetaTool과 ToolBench 데이터셋에서 여러 LLM과 검색기를 대상으로 실험했다. 평가에는 악성 도구가 검색 후보에 포함되는 비율인 AHR과 최종적으로 선택되는 비율인 ASR 등이 사용됐다. GPT-4o를 대상으로 한 실험에서 기울기 비사용 방식은 MetaTool에서 96.7%, ToolBench에서 88.2%의 ASR을 기록했다. 또한 정상 도구가 9,650개인 환경에 악성 문서 하나만 추가해도 약 96∼98%의 높은 AHR이 나타났다.

ToolHijacker는 검색과 선택을 함께 최적화했기 때문에 기존 수동 공격과 자동 공격보다 높은 성공률을 보였다. StruQ, SecAlign, DataSentinel, PPL, PPL-W 등의 방어 기법도 평가했지만 공격을 충분히 방어하지 못했다. 특히 자연스럽게 작성된 기울기 비사용 악성 문서는 기존 탐지 방식으로 구별하기 어려웠다. 다만 논문은 악성 도구가 선택되는지를 중심으로 평가했으며, 선택 이후 실제 호출과 실행에서 발생하는 피해까지는 직접 실험하지 않았다.

결

이 논문을 읽으면서 프롬프트 인젝션에도 다양한 공격 방식이 있다는 점이 흥미로웠다. 특히 LLM 에이전트가 사용자의 요청을 받은 뒤 관련 도구를 검색하고, 후보 중 하나를 선택하는 구조를 이해하는 데 도움이 되었다. 또한 공격 성공률과 악성 도구 검색률 같은 지표를 통해 공격 성능을 평가한다는 점과, 기울기 기반·비사용 방식으로 공격 문장을 최적화할 수 있다는 점도 새롭게 알게 되었다.

다만 기존 방어 기법들이 ToolHijacker를 충분히 막지 못했다는 결과에 비해, 구체적인 방어 방법과 공격 성공 이후 발생할 수 있는 피해에 관한 실험이 자세히 제시되지 않아 아쉬웠다. 앞으로는 악성 도구 설명을 어떤 기준으로 탐지하고 차단할 수 있을지 생각해 보고, 사용자 요청과 도구 설명의 일치 여부를 별도의 LLM이 검증하는 방어 방법도 실험해 보고 싶다. 우선 해볼 것은 나이츠 프론티어 미션의 Lakera 사이트를 활용해 프롬프트 인젝션 실습을 진행할 예정이다. 이후에는 에이전트의 도구 호출과 실행 단계까지 다루는 *AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents*를 읽어볼 계획이다.

- 모르는 단어나 개념 또는 헷갈린 것들
    1. 에이전트는 사용자의 요청을 이해하고, 필요한 도구를 스스로 골라 작업을 수행하는 AI 시스템
    2. no-box는 대상 시스템의 내부 정보에 거의 접근할 수 없는 환경을 뜻함
    3. 정식화는 어떤 문제를 수학식이나 명확한 규칙으로 표현하는 것
    4. 인코더는 글이나 이미지 같은 정보를 컴퓨터가 처리할 수 있는 숫자 형태로 변환하는 장치나 모델
    5. 아키텍처는 시스템이 어떤 구조와 방식으로 설계되어 있는지를 뜻함
    6. 임베딩 벡터는 문장이나 단어의 의미를 여러 개의 숫자로 표현한 것
    7. 매핑은 하나의 값을 다른 값과 연결하거나 대응시키는 것
    8. 머리말 지시는 원래 내용의 앞부분에 넣는 지시
    9. 꼬리말 지시는 원래 내용의 뒷부분에 넣는 지시
    10. 메커니즘은 어떤 현상이나 시스템이 작동하는 원리와 과정을 뜻함
    11. MCP(Model Context Protocol)는 AI가 외부의 도구나 데이터와 연결되는 방법을 표준화한 규칙
    12. 파이프라인은 입력이 결과로 나오기까지 작업이 이어지는 처리 순서와 흐름
    13. 시퀀스는 특정 목적에 맞게 구성된 문구 또는 문자열
    14. 기울기는 어느 방향으로 값을 바꿀 때 오차가 커지는지 알려주는 정보
    15. 기울기 기반 방법은 모델 내부의 기울기(gradient) 정보를 이용해, 어떤 단어나 토큰을 바꾸면 목표 점수가 높아질지 계산하는 방식
    16. 기울기 비사용 방법은 기울기 정보를 보지 않고 여러 문구를 직접 만들어 시험한 뒤, 점수가 더 좋은 문구를 선택하며 개선하는 방식
    17. 기울기 하강법은 그 반대 방향으로 이동하여 오차를 줄이는 방법
    18. 하이퍼파라미터는 학습이나 최적화를 시작하기 전에 정하는 설정값
    19. HotFlip는 기울기를 참고하여 가장 효과적인 단어 교체를 반복하는 최적화 방법
    20. 퍼플렉서티는 문장이 언어 모델에게 얼마나 낯설고 이상하게 느껴지는지를 나타내는 값
    21. 퍼플렉서티 손실(perplexity loss)은 생성된 문장이 얼마나 자연스럽고 언어 모델이 예상하기 쉬운지 측정하는 값
    22. MetaTool은 LLM의 도구 판단·선택 능력을 시험하는 문제집
    23. AHR(Attack Hit Rate)은 공격 적중률임 악성 도구 문서가 검색 단계에서 상위 k개의 후보 목록에 포함된 비율을 뜻
    24. ASR은 검색부터 최종 선택까지 전체 공격의 성공률
    25. FNR은 실제 공격 중 탐지기가 놓친 공격의 비율 (미탐률)
    26. FPR은 탐지기가 정상인 사람에게 잘못 울린 경보의 비율(오탐률)
    27. StruQ는 지시와 데이터를 구분해서 공격을 예방
    28. SecAlign은 정상적인 응답을 더 선호하도록 학습
    29. DataSentinel은 탐지용 LLM으로 악성 지시를 찾아냄
    30. PPL은 전체 문장의 이상함을 수치로 측정하여 방어하는 기법
    31. PPL-W는 문장을 구간별로 나누어 이상함을 측정하여 방어하는 기법
    32. 휴리스틱은 항상 완벽하진 않지만, 경험상 잘 통하는 빠른 판단 방법
